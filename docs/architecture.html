Communication Patterns

Service-to-Service Communication

  • Apollo → PostgreSQL: Direct database connection via secret-managed credentials
  • Apollo → Redis: Uses bundled Redis by default or externalRedis when configured
  • Apollo → Thermos: Internal orchestration path for background work
  • Apollo → Weaviate: Search / vector lookups when Weaviate is enabled; this is the default chart state
  • Thermos → Mercury: HTTP execution path via the in-cluster Mercury service
  • Thermos → Temporal: Optional workflow path enabled only by features.temporal=true
  • Mercury → Apollo / External APIs: Uses Apollo for control flow and external providers for tool execution
  • Frontend → Apollo: Optional browser-facing path when frontend.enabled=true

Security Architecture

  • Secrets Management: Kubernetes Secrets provide admin, encryption, JWT, database, Redis, and provider credentials
  • Service Accounts: Apollo has a dedicated service account by default; other workloads expose configurable security settings
  • Container Hardening: Mercury defaults to a non-root security context with dropped capabilities
  • Registry Access: Images are pulled through Replicated or user-provided global.imagePullSecrets
  • Ingress / TLS: Apollo, Frontend, and Mercury expose separate optional ingress blocks

Data Flow

  • API Flow: Client → Apollo → PostgreSQL / Redis → Response
  • Search Flow: Apollo → Weaviate → optional reranker / model provider → Response
  • Tool Execution Flow: Apollo → Thermos → Mercury → external API → Apollo / Response
  • Frontend Flow: Browser → optional Frontend / ingress → Apollo
  • Workflow Flow: Thermos → Temporal only when Temporal is enabled
  • Observability Flow: Services → OTEL Collector only when OTEL is enabled
  • Object Storage: Apollo supports optional S3 or Azure Blob Storage configuration

External Dependencies

Required

  • Kubernetes: Cluster capable of running the chart and bundled dependencies
  • PostgreSQL: External database plus credentials secret
  • Chart Secrets: Core secret values for admin token, encryption, JWT, and database URLs
  • Registry Authentication: Replicated pull secret or equivalent image pull credentials

Optional

  • External Redis: Replaces the bundled Redis chart
  • Frontend / Ingress: Browser UI and external routing
  • Temporal / OTEL / Knative: Feature-specific add-ons
  • OpenAI / Bedrock / Object Storage Credentials: Required only for enabled integrations

Deployment Modes

Default Chart Render

  • features.temporal=false
  • otel.enabled=false
  • frontend.enabled=false
  • mercury.useKnative=false
  • redis.enabled=true and weaviate.enabled=true

Extended / Production-Oriented Render

  • Enable frontend and ingress for browser access
  • Use external Redis when a managed cache is preferred
  • Enable Temporal for auth refresh and trigger workflows
  • Enable OTEL for traces and metrics export
  • Switch Mercury to Knative only when serverless scaling is required
